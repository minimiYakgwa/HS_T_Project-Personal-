# Project HS-T 기록

이 문서는 Project HS-T의 주요 의사결정과 AI 활용 내역을 저장소 버전과 함께 추적하기 위한 기록입니다. 상세 기획은 [Project-HS-T Notion](https://www.notion.so/Project-HS-T-3ba95561a55c80a9be21c65415ccc4c8)에 유지합니다.

## 기록 원칙

- 게임 코드는 개발자가 직접 작성합니다.
- AI는 코드 검토, 개선 제안, 프로젝트 LOG 작성, Notion 기획 및 변경 기록만 담당합니다.
- AI가 제시한 내용은 `제안`, 개발자가 채택한 내용은 `확정`, 추가 판단이 필요한 내용은 `검토`로 구분합니다.
- 기획 변경 시 변경 이유, 영향 범위, 검증 방법과 AI 관여 범위를 기록합니다.
- AI가 코드 생성 또는 수정에 관여했는지 각 항목에 명시합니다.

## 2026-08-26

### 개발 방법론 및 소프트웨어 공학 방향 검토

- 구분: 제안 및 검토
- AI: ChatGPT / Codex
- 목적: 1인 개발 JRPG의 프로세스, 테스트, DOD, ECS, 데이터 저장 및 아키텍처 방향 검토
- 결과:
  - 1~2주 스프린트와 칸반을 결합한 Scrumban을 제안했습니다.
  - 전투 프로토타입과 수직 슬라이스 우선 개발을 제안했습니다.
  - 기능·콘텐츠·릴리스 작업별 Definition of Done 적용을 제안했습니다.
  - Data-Oriented Design은 대량 처리 구간에 선택적으로 적용하고, ECS 전면 도입은 기술 실험과 프로파일링 전까지 보류하는 방향을 제안했습니다.
  - 초기 싱글 플레이 런타임에는 서버 데이터베이스가 불필요하지만 데이터 ID, 저장 버전 및 마이그레이션 설계가 필요하다고 검토했습니다.
- 최종 결정 주체: 개발자
- 코드 생성·수정: 없음

### 전투 기획 및 협업 범위 확정

- 구분: 확정 및 검토
- AI: ChatGPT / Codex + Notion
- 확정된 내용:
  - Unity 6 기반 3D 게임으로 개발합니다.
  - 실시간 필드 전투는 약한 일반 적을 매번 턴제로 처리해야 하는 반복 피로를 줄이기 위한 보조 전투 계층입니다.
  - 물리 공격뿐 아니라 마법 공격에도 크리티컬 판정을 적용합니다.
  - 게임 코드는 개발자가 직접 작성하며, AI는 코드 검토·제안·LOG·Notion 기록만 담당합니다.
- 검토가 필요한 내용:
  - 약점과 마법 크리티컬의 중첩 규칙
  - 다단 히트, 지속 피해, 회복 및 상태이상의 크리티컬 적용 범위
  - 실시간 전투와 턴제 전투의 전환 조건 및 선제권 보상
- Notion 반영: Project-HS-T 페이지에 기획서 기준본을 생성했습니다.
- 코드 생성·수정: 없음
